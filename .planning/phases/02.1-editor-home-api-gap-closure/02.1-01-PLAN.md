<current_findings>
- `ContentBlockEditor.tsx` imports `@blocknote/react/style.css` and renders `BlockNoteViewRaw` inside a `.bn-container`, but it does not pass BlockNote's `theme` prop.
- BlockNote v0.51.2 supports `BlockNoteViewRaw theme?: "light" | "dark"` and renders `.bn-root[data-color-scheme="dark"]`; its default dark CSS uses `--bn-colors-editor-background: #1f1f1f`, which can read as a black editor in this admin UI.
- Project theme state lives in `frontend/src/stores/themeStore.ts`; `ThemeToggle` mirrors it to `document.documentElement.classList`.
- Current editor already enables `linkToolbar`, `slashMenu`, `sideMenu`, `tableHandles`, custom formatting toolbar, table delete button, `uploadFile`, and markdown-oriented `pasteHandler`; the gap is that real browser verification is still missing and theme/readability remains unproven.
- `ContentBlockPreview.tsx` currently uses a headless BlockNote editor and `editor.blocksToFullHTML(initialContent)` with prose styling; executor must verify it still reflects saved content.
</current_findings>

<interfaces>
BlockNote v0.51.2 relevant props:

```typescript
type BlockNoteViewProps = {
  editor: BlockNoteEditor
  theme?: 'light' | 'dark'
  editable?: boolean

} & BlockNoteDefaultUIProps

type BlockNoteDefaultUIProps = {
  formattingToolbar?: boolean
  linkToolbar?: boolean
  slashMenu?: boolean
  sideMenu?: boolean
  tableHandles?: boolean

```

Project theme store:
