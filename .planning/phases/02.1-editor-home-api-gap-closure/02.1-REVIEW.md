## Warnings

### WR-01: Missing error handling and loading state in `handleBodyImageUpload`

**File:** `frontend/src/components/admin/content/AdminContentEditor.tsx:185-188`
**Issue:** The `handleBodyImageUpload` function lacks both error handling and loading state management, unlike the two other upload functions in the same component (`handleCoverUpload` at line 161 and `handleScreenshotUpload` at line 172). If `uploadImage` throws (network failure, server error, file too large), the rejected promise propagates to BlockNote's internal upload handler with no user-facing error feedback. Additionally, there is no `isUploading` indicator while the body image upload is in progress, so the user sees no loading state and might attempt duplicate uploads.

```typescript
// Current — no error handling, no loading state
async function handleBodyImageUpload(file: File) {
    const uploaded = await uploadImage(file, bodyPurpose[kind])
    return uploaded.url
}
```

**Fix:** Wrap in try-catch and provide loading feedback consistent with the other handlers.

```typescript
async function handleBodyImageUpload(file: File) {
    setIsUploading(true)
    try {
        const uploaded = await uploadImage(file, bodyPurpose[kind])
        return uploaded.url
    } catch (err) {
        console.error('Body image upload failed:', err)
        // Optionally surface error to user via toast/notification
        throw err // Let BlockNote know the upload failed so its handler can clean up
    } finally {
        setIsUploading(false)
    }
}
```

### WR-02: Potential crash from `blocksToFullHTML(undefined)` when content is empty

**File:** `frontend/src/components/admin/editor/ContentBlockPreview.tsx:13-30`
**Issue:** When `value` is `undefined` or an empty array (`[]`), the `initialContent` useMemo returns `undefined` (lines 13-18). This `undefined` is then passed directly to `editor.blocksToFullHTML(initialContent)` at line 28. BlockNote's `blocksToFullHTML` method signature expects `PartialBlock[]` in its current API — it may not handle `undefined` gracefully. If the method performs array operations (`.length`, iteration) on the argument without a null guard, this will throw a runtime TypeError, crashing the component. This component is imported and used in four admin pages: `AdminContentEditor`, `AdminArticles`, `AdminNotes`, and `AdminProjects`.

```typescript
// Current — initialContent can be undefined
const html = useMemo(
    () => editor.blocksToFullHTML(initialContent),
    [editor, initialContent],
)
```

**Fix:** Provide a fallback empty array.

```typescript
const html = useMemo(
    () => editor.blocksToFullHTML(initialContent ?? []),
    [editor, initialContent],
)
```

### WR-03: `dangerouslySetInnerHTML` rendering without defense-in-depth sanitization

**File:** `frontend/src/components/admin/editor/ContentBlockPreview.tsx:34-35`
**Issue:** The component renders BlockNote-produced HTML using `dangerouslySetInnerHTML={{ __html: html }}` without any additional sanitization layer. While BlockNote is expected to sanitize its own HTML output, defense-in-depth practice recommends a secondary sanitizer (e.g., DOMPurify) on any user-originated content rendered via `dangerouslySetInnerHTML`. If a BlockNote version update introduces a sanitization regression, or if block JSON is manipulated externally before being loaded, this could become an XSS vector. Risk is mitigated by admin-only usage (self-XSS), but the component is reusable and may be exposed to broader contexts later.

**Fix:** Add DOMPurify as a sanitization pass.

```typescript
import DOMPurify from 'dompurify'

// Inside the component:
const html = useMemo(
    () => DOMPurify.sanitize(editor.blocksToFullHTML(initialContent ?? [])),
    [editor, initialContent],
)
```

## Info

### IN-01: Duplicate handler logic between AdminArticles and AdminNotes pages

**File:** `frontend/src/pages/Admin/AdminArticles.tsx:65-100` and `frontend/src/pages/Admin/AdminNotes.tsx:65-100`
**Issue:** The `handleSaveDraft`, `handlePublish`, and `runRowAction` functions are structurally identical between the two page components, differing only in the mutation hook names (`createArticle` vs `createNote`, etc.) and navigation paths (`/admin/articles` vs `/admin/notes`). This duplication means any bug fix or behavior change must be applied in both places, creating a maintenance burden and risk of drift.

**Fix:** Extract the shared pattern into a reusable hook or higher-order function parameterized by the content kind. For example, a `useAdminContentHandlers(kind, hooks, navigate)` hook that returns `handleSaveDraft`, `handlePublish`, and `runRowAction`.

### IN-02: Unnecessary data fetching in FeaturedProjects

**File:** `frontend/src/components/home/FeaturedProjects.tsx:90,93`
**Issue:** The component fetches up to 10 projects (`pageSize: 10`) but only displays the first 3 (`visibleProjects.slice(0, 3)`). The extra 7 projects are transferred over the network and hydrated on the client but never rendered, wasting bandwidth and increasing the API response payload.

```typescript
const { data, isLoading, isError } = usePublicProjects({ pageSize: 10 })
// ...
const visibleProjects = displayProjects.slice(0, 3)
```

**Fix:** Reduce `pageSize` to match the display count.

```typescript
const { data, isLoading, isError } = usePublicProjects({ pageSize: 3 })
```

### IN-03: Fragile runtime type discrimination in `toEditorValue`

**File:** `frontend/src/components/admin/content/AdminContentEditor.tsx:447-465`
**Issue:** The `toEditorValue` function uses runtime property checks (`'category' in value`, `'noteType' in value`, `'projectStatus' in value`, etc.) to discriminate the `Article | Note | Project` union type. This pattern is fragile: if a new property with the same name is added to a different content type in the future, the discrimination silently produces incorrect values (e.g., a Note gaining a `category` field would cause `noteType` to be set to `'short'` while `category` is correctly read).

**Fix:** Use a discriminated union with a `kind` property (`'article' | 'note' | 'project'`) for type-safe narrowing via `switch`, or at minimum add an explicit `kind` parameter to `toEditorValue` so the discrimination is explicit rather than inferred from property presence.

### IN-04: Type assertion `as any` for BlockNote dictionary

**File:** `frontend/src/components/admin/editor/ContentBlockEditor.tsx:109-116`
**Issue:** The BlockNote dictionary configuration object is cast to `any` to bypass TypeScript type checking. While the comment documents the intent ("vendor-specific; cast is intentional at the adapter boundary"), this completely disables type safety for the dictionary object. A typo in a placeholder key or a missing required field would go undetected at compile time.

```typescript
dictionary: {
    placeholders: {
        emptyDocument: emptyPrompt,
        default: emptyPrompt,
    },
} as any,
```

**Fix:** Use a more targeted type suppression, e.g., a local type alias matching the relevant subset of BlockNote's dictionary type, or `@ts-expect-error` on the specific incompatible line rather than casting the entire object to `any`.

### IN-05: `void` operator silently discards promise rejections in onClick handlers

**File:** `frontend/src/components/admin/content/AdminContentEditor.tsx:238,247,258`
**Issue:** The Save Draft, Publish, and Soft Delete buttons use the `void` operator to suppress the floating-promise lint warning:

```typescript
onClick={() => void onSaveDraft(currentValue)}
onClick={() => void onPublish(currentValue)}
onClick={() => void onSoftDelete()}
```

While the parent handlers (`AdminArticles.handleSaveDraft`, etc.) use React Query mutations that manage their own error state, the `void` operator discards the promise entirely. If a synchronous exception occurs before the mutation is called, or if a non-React-Query rejection escapes, it becomes an unhandled promise rejection visible only in the browser console — not surfaced to the user.

**Fix:** Attach a `.catch()` to the promise for explicit error logging, or use an async IIFE with try-catch.

```typescript
onClick={() => { onSaveDraft(currentValue).catch(console.error) }}
```
