<diagnosis_summary>
All six gaps diagnosed in detail with root causes:

**Gap 1 (Stat counts = 0):** AdminOverview.tsx lines 20-42: `stats` is a hardcoded module-level `const` with all counts zero. Component never imports useAdminArticles/useAdminNotes/useAdminProjects hooks from `@/hooks/useAdminContent.ts`. Those hooks already exist (lines 94, 158, 222), return `{ items, total }`, and are used by AdminArticles/AdminNotes/AdminProjects pages.

**Gap 2 (Recent edits empty):** Two layers broken: (a) `hasContent` at line 51 checks `stats.some(s => s.count > 0)` — always false because stats are hardcoded to 0, so the "还没有内容" empty state always shows. (b) The else branch at line 138 renders static "暂无最近编辑内容" text with no data fetching whatsoever.

**Gap 3 (Table deletion):** BlockNote v0.51.2 TableHandleMenu exports only AddButton (row/column add) and DeleteButton (row/column delete) — no whole-table delete button. Users must find the side-menu drag handle's RemoveBlockItem, a separate interaction area.

**Gap 4 (Inline toolbar):** BlockNote v0.51.2 BlockNoteDefaultUIProps defines formattingToolbar as `boolean` only. No position/inline/block-bound mode exists. This is a version-level constraint — only BlockNote v0.60+ adds object-form toolbar config.

**Gap 5 (Preview HTML):** ContentBlockPreview.tsx renders a read-only BlockNoteViewRaw — same editor-styled blocks, not public-facing output. BlockNote's `blocksToFullHTML()` API exists in `@blocknote/core` but is unused.

**Gap 6 (Markdown paste):** BlockNote has built-in markdown support with `prioritizeMarkdownOverHTML` and `plainTextAsMarkdown` both defaulting true, BUT when clipboard has both text/html AND text/plain (common from browser/rich-text sources), HTML wins unless isMarkdown() returns true for the plain text — and isMarkdown() has conservative regex patterns. No custom pasteHandler is configured.
</diagnosis_summary>

Three independent fixes across two files:

**A) Table whole-block deletion (ContentBlockEditor.tsx):**
BlockNote v0.51.2's tableHandles menu provides only row/column add/delete buttons. Add a custom menu item for whole-table deletion.

Research approach: BlockNote v0.51.2 BlockNoteDefaultUIProps accepts `tableHandles?: boolean`. However, v0.51.2 does NOT support custom table handle menu items via props — the TableHandleMenu DefaultButtons (AddButton, DeleteButton) are the only options.

Fallback approach that works on v0.51.2:
1. Add `onClick` handler to the bn-container div that captures right-click or auxiliary clicks
2. OR: add a wrapper div with a subtle "Delete table" button positioned absolutely when a table block is focused/hovered
3. Simplest practical approach: add a custom `formattingToolbar` menu extension — BlockNote v0.51.2 supports custom formatting toolbar items. Create a custom toolbar button "Delete Table" that:
   - Is only enabled when the selected block is a table block
   - On click: gets the table block ID from getTextCursorPosition().block, traverses up if inside a table cell, calls editor.removeBlocks([tableBlockId])
   - This integrates with the existing formatting toolbar pattern

Implementation:
- Import type { BlockNoteEditor } from '@blocknote/core'
- In useCreateBlockNote options, add a custom formatting toolbar config (if BlockNote v0.51.2 supports custom formatting toolbar items — check the types; if not, add the delete-table button as a custom sideMenu item instead)
- If formatting toolbar customization is not available in v0.51.2, add a custom React button outside BlockNoteViewRaw that appears when a table block is selected, calls `editor.removeBlocks([tableBlockId])`

If all custom-menu approaches fail due to v0.51.2 API limitations: add a `useEffect` that attaches a keyboard shortcut (e.g., Ctrl+Shift+Backspace) to delete the currently focused table block. Document the shortcut in a tooltip.

**B) HTML preview (ContentBlockPreview.tsx):**
Replace the read-only BlockNoteViewRaw with HTML rendering:
- Import { blocksToFullHTML } from '@blocknote/core'
- Remove the useCreateBlockNote + BlockNoteViewRaw setup
- Compute HTML string via blocksToFullHTML: `const html = blocksToFullHTML(value as PartialBlock[], editor.schema)` — but since we no longer create an editor, we need the schema differently
- Alternative approach that works: keep useCreateBlockNote for HTML generation only (no BlockNoteViewRaw), call `await editor.blocksToFullHTML(editor.document)` on the editor created with the value blocks, then render the HTML string via dangerouslySetInnerHTML
- The editor instance is created (once, via dependency array with [JSON.stringify(value)]) purely for HTML export; no visual editor rendering
- Wrap the HTML output in a div with className "prose prose-sm dark:prose-invert max-w-none" for Tailwind Typography styling matching public blog appearance
- Keep a loading state while the editor initializes (brief moment)

**C) Markdown paste handling (ContentBlockEditor.tsx):**
Add pasteHandler to useCreateBlockNote options:
```typescript
pasteHandler: ({ defaultPasteHandler }) => {
  return defaultPasteHandler({
    prioritizeMarkdownOverHTML: true,
    plainTextAsMarkdown: true,
  })
}
```
This ensures: (1) when isMarkdown() detects markdown patterns, it wins over HTML, (2) plain text without HTML is always treated as markdown. Note: when clipboard has both text/html AND text/plain AND isMarkdown() returns false for the plain text, HTML may still win — this is a known BlockNote v0.51.2 limitation. Most common markdown paste scenarios (multi-line, headers, lists, code blocks) will work.
