<decision_coverage>
D-01: shared fields/status/soft-delete contracts are defined for separate content models.
D-02: `BlockContentDto` treats editor-native JSON as canonical body content.
D-03: shared contracts omit Markdown, HTML, and plain-text body storage.
D-04: shared tags/status are defined without forcing model-specific fields into one schema.
D-05: slug generation helper supports automatic unique slug flows.
D-07: upload purposes preserve URL-reference image handling without media-library scope.
D-22: shared content status vocabulary defines draft, published, and archived.
D-23: soft-delete metadata is part of the shared content contract.
D-28: shared contracts support separate admin/public route boundaries in downstream plans.
</decision_coverage>

<threat_model>
STRIDE register:
- T01-01 Tampering: malformed editor JSON could be persisted. Mitigation: create `BlockContentDto` and service-facing body type that accepts JSON values only, per D-02/D-03, with no HTML execution path.
- T01-02 Elevation of privilege: new upload purposes could widen public upload access. Mitigation: keep the existing `UploadController` `@Roles('admin')` guard and expand only the enum allowlist, per D-26 and INFR-04.
- T01-03 Information disclosure: archived/deleted content could later leak if filters diverge. Mitigation: shared status and soft-delete helper names must be used by all content services, per D-22/D-23/D-27.
</threat_model>
