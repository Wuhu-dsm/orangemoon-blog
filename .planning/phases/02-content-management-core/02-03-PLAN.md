GOAL: gives the blogger note creation/editing APIs for the content-production core.
REQ: covers NOTE-05 and the note portion of ADMN-03.
RESEARCH: follows the backend content slice pattern established by article while keeping route boundaries separate.

<decision_coverage>
D-01: note has its own module/model while using shared title, slug, summary, coverImage, tags, status, timestamps, and soft delete.
D-02: note body persists editor-native JSON.
D-03: note schema excludes synchronized Markdown, HTML, and plain text body fields.
D-04: noteType stays note-specific while tags remain shared.
D-05: note service generates and validates unique note slugs.
D-06: note schema and DTOs keep a summary field without implementing AI summary generation.
D-07: note images are URL references from upload output.
D-22: note status transitions support draft, published, and archived/unpublished semantics.
D-23: note delete is soft delete.
D-26: admin note writes require admin role.
D-27: public note reads expose published non-deleted data.
D-28: public and admin note routes are separate.
</decision_coverage>

<threat_model>
STRIDE register:
- T03-01 Information disclosure: unpublished notes leak into public note APIs. Mitigation: service public reads filter status and deleted metadata per D-22/D-23/D-27.
- T03-02 Elevation of privilege: visitor writes notes. Mitigation: all admin note writes are under `admin/notes` and guarded with `@Roles('admin')` per D-26/D-28.
- T03-03 Tampering: note slug edits collide with another note. Mitigation: service validates uniqueness within notes and suffixes generated slugs per D-05.
</threat_model>
