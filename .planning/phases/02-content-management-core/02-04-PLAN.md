<decision_coverage>
D-01: project has its own module/model while using shared title, slug, summary, coverImage, tags, status, timestamps, and soft delete.
D-02: project body persists editor-native JSON.
D-03: project schema excludes synchronized Markdown, HTML, and plain text body fields.
D-04: projectStatus and project fields stay project-specific while tags remain shared.
D-05: project service generates and validates unique project slugs.
D-06: project schema and DTOs keep a summary field without implementing AI summary generation.
D-07: project covers/screenshots are URL references from upload output.
D-22: project status transitions support draft, published, and archived/unpublished semantics.
D-23: project delete is soft delete.
D-26: admin project writes require admin role.
D-27: public project reads expose published non-deleted data.
D-28: public and admin project routes are separate.
</decision_coverage>

<threat_model>
STRIDE register:
- T04-01 Information disclosure: unpublished projects leak publicly. Mitigation: public service methods filter `published` and non-deleted documents per D-22/D-23/D-27.
- T04-02 Elevation of privilege: visitor creates or deletes projects. Mitigation: all management endpoints live under `admin/projects` with `@Roles('admin')` per D-26/D-28.
- T04-03 Spoofing/tampering: external project links or screenshots contain unsafe values. Mitigation: DTOs validate URLs as URL strings and keep uploaded screenshots as URL references per D-07.
</threat_model>
